# 独立应用架构与数据口径

## 运行边界

React 前端通过同源 `/api/v1` 访问 Go 服务。Go 服务负责身份、授权、业务记录、模型调用与知识检索。SQLite 保存业务与任务状态，本地受保护文件目录保存图像和文档。模型地址和密钥由本项目独立配置。

没有 yx 平台的模块引用、远程登录、数据库连接、知识库接口或运行时依赖。参考的仅是兼容模型请求、图片内容和流式处理的工程方法。

## 学习数据流

1. 上传文件并校验真实类型；创建样本与背景版本。
2. 学习轮次固定引用样本快照，创建分析任务。
3. worker 读取图片、检索已发布资料，调用模型并校验结果。
4. AI 原始报告单独保存；学生修正追加版本，不覆盖原稿。
5. 五维学习完成后形成个人图谱条目；教师查看、反馈与复核保留各自记录。
6. 复练任务关联下一轮，历史图谱与判断始终可以回溯。

## 核心实体

| 实体 | 作用与边界 |
| --- | --- |
| 用户、会话、班级成员 | 定义真实身份和资源权限；角色由服务器读取 |
| 文件 | 保存受保护的原始内容；文件 ID 不能绕过样本与资料权限 |
| 样本与版本 | 保存材料、工艺、倍率、腐蚀剂及图片背景 |
| 学习轮次 | 固定样本快照、步骤、父轮次与复练任务关联 |
| 规则与版本 | 保存教学规则；个人修改不覆盖公共版本 |
| AI 报告 | 保存模型、提示词、样本、规则、检索来源与初始结果 |
| 学生修订 | 保存最终内容、修正依据与版本；并发修改需要冲突检查 |
| 教师记录 | 查看、反馈、确认或要求修订，分别记录操作者与时间 |
| 练习任务与提交 | 区分草稿/发布，按学生记录完成状态 |
| 图谱条目 | 区分个人学习资料、共享已发布资料和示例资料 |
| 文档与知识片段 | 保存内容及来源；公共检索只返回已发布资料 |
| 任务及事件 | 保证异步状态、SSE 回放、取消与显式重试可追溯 |

## 得分与观察口径

得分属于学习反馈，不用于排名或竞赛成绩。服务端按合法分项计算总分；无法观察的项目保持为空，并呈现可评价范围，不按零分处理。

AI 建议分、学生最终分和教师反馈分别展示。更换评分规则、样本版本或观察条件时，趋势需要区分口径，不把这些变化直接归因为能力提高。统计展示时间范围、记录数和分母；没有数据或可比较记录不足时显示空状态。

模型对图像的观察、用户提供的背景和知识资料推断需要分别标识。图片中的缺陷标注仅是待核对的参考定位，不代表像素分割。数值性能不能从单张图片直接生成实测结论。

## AI 及检索约束

模型无权执行数据库操作或调用任意工具。输入中的图片、学生文字和资料片段均作为分析内容，不能修改系统输出协议。输出先进行结构校验，再校验分数、引用及标注范围；不通过的响应不能成为正式报告。

引用只能指向本次实际检索到的资料。没有资料命中时明确标识证据不足。个人修正不是已验证知识，不自动进入公共资料库或模型训练。

## 任务一致性

创建任务与浏览器订阅分离。任务进度落库后以标准 SSE 发送，断线使用事件序号续接。只有校验通过且任务仍处于可完成状态时才保存报告与成功事件。取消、失败或服务中断不会显示为成功。

模型请求期间不持有数据库事务。客户端幂等键避免重复点击重复创建任务。任务中断不会自动重发外部模型请求，以免隐性重复计费。
