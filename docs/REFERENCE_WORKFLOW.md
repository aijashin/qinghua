# 见微知著：资料复用与分析测试指南

## 规则立即可用

打开“平台治理 → 评分规则”，启动后已有“金相制样学习评价 v1”：划痕、假象、侵蚀程度、组织清晰与正确度各25分，包含良好、轻微、明显和严重影响的文字判据。这是教学反馈规则，不是国赛官方成绩标准。管理员可以复制、编辑、发布新规则；自建已发布版本优先使用，历史评分不变。

## 资料怎样进入模型

这里使用关键词RAG，而非向量RAG：文本约700字分段，重叠约80字，中文单字和相邻二元词索引到SQLite FTS5，查询优先二元词，使用BM25排序。自动分析查询取已知材料、工艺、个人判断和问题，跳过明确“未知”，不是先让模型猜组织再检索。

每次最多提供6个文档片段，以及2张文字相关的参考图谱/教学案例。参考资料标题、背景和观察依据建立文字索引，召回后图片真正进入视觉请求。没有做图片相似度或像素分割；材料或工艺相似不保证组织相同。当前样本与参考图片分开标记，所有评分和标注只针对当前样本。

发布资料只增加可检索上下文，不训练模型。个人修正、仅查看或仅反馈不会进入公共知识库。

## 管理员测试资料

1. 在“知识资料”上传含中文材料、工艺关键词的讲义。导入完成后点“预览 / 发布”，在弹窗核对正文、版本、标签及检索片段，确认发布。
2. 在“参考图谱”上传有来源的真实图片，填写材料、工艺、组织和观察依据，审核发布。模型不会自动认证这张图的组织标签。
3. 学生上传有对应背景的新照片，发起评图或五维理解。在“查看处理详情”核对召回数量和资料标题。结果中点击引用，可阅读正文与参考图片；检索到不等于模型最终引用。
4. 删除资料：确认弹窗明确保留历史引用。删除后新分析不能检索，既有报告仍能阅读当时引用。已经检索到该资料的运行中任务保留本次快照。删除版本冲突时重新预览后再操作。

## 教师案例完整流程

1. 学生将真实样本关联到班级，完成报告并保存个人判断。
2. 教师在“学习记录”检查原图、AI原稿和学生稿，填写理由并“保存复核决定”。查看和指导不算确认；旧版本复核不能替代新稿复核。
3. 点击“创建案例草稿”，在弹窗编辑匿名标题、组织判断、教学结论、观察依据和说明。核对正文中没有姓名或账号，保存草稿后单独“发布到班级”。
4. 在“教学案例”管理已发布记录。修改形成新版本草稿，发布后替换旧版；撤回停止新召回但保留历史引用。
5. 同班学生选择该班级的新轮次，填写可匹配背景并分析，检查案例召回。个人练习默认只检索公共资料。其他班级不能读取班级案例或参考图片。
6. 管理员在“平台治理 → 教师案例”预览班级案例并“审核并公开”，之后才能供其他班级和个人练习检索。
7. 学生再次修改后，原复核不再表示确认当前稿。发布过的案例是冻结版本，不会自动随学生记录变化。

## 进度和识相悟道

进度显示全部待处理步骤，当前阶段持续计时，不提供假百分比。详情可查看图片格式/尺寸、召回数量、请求和响应时刻、首个内容块等待、实际接收字节与块数、校验状态；token只显示供应商实际提供的数量。遇到格式错误最多修复一次，取消/超时/中断不会生成伪成功报告。

识相悟道的“我的版本”展示组织、判断依据、修订时间和记录理由，支持AI候选对照。五维卡片分别展示背景/观察/推断及修正状态。组织修改不会自动改写五维解释，需要自行核对相关维度。保存失败和409冲突会保留弹窗草稿。

## 本地验证命令

```sh
cd backend
go test ./...
go test -race ./internal/app ./internal/ai ./internal/jobs ./internal/observability
go vet ./...
cd ..
npm run build
npm run lint
npm run test:ui
python3 scripts/validate_openapi.py
python3 scripts/e2e.py
```

`test:ui`是组件语义渲染和SSE去重测试，不能替代浏览器交互、焦点和375/768/1440px目视验收。浏览器自动化此前不可用，不能据此声称已完成视觉验收。

真实模型联调使用隔离数据库，不改变正式记录：

```sh
./scripts/check-model.sh --image /path/current.jpg --reference-image /path/reference.jpg --kind understanding
```

可添加第二个`--reference-image`。先做随机数字图片读取探测，再验证当前图片与参考图片进入实际请求、结构校验、引用和保存。这不证明专业组织判断准确，参考图片在隔离测试中明确标为接口联调照片。
